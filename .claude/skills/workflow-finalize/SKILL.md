# Finalize

Run this phase only in a conversation where the user ran `/work`. Otherwise stop: don't run the phase, handle the request as an ordinary one.

Read `~/.claude/workflow/rules.md` first (explicit-direction precedence applies; safety and helper checks stay). Input: $ARGUMENTS (plan path plus notes with report paths). A chat request or authorized handoff is enough to start: no extra approval, browser review, receipt, worktree comparison or clean-index check. Git inspection is needed before publication, not before consolidation. Helper: `H=~/.claude/workflow/task.sh`.

## 1. Consolidate (every task)

1. **Target.** Read the whole plan and applicable instructions. Given a report, resolve its implementation plan through its references; ask if ambiguous or missing. The plan path survives as the summary. Consult source/history only to understand the task; don't claim checks were rerun.
2. **Inputs.** Before editing, fix the exact set of eligible paths: this task's plan, related plans, clarifications, reviews, blocker and UI/feedback reports, from links and handoff notes, plus clearly related reports in the artifact dirs that reference the plan. Read them completely. Filename prefix or mtime alone doesn't prove membership; don't bulk-read history. Files outside the artifact dirs are never deletion targets. Ask when membership, shared artifacts, targets, conflicting decisions, unreadable inputs or reasons are unclear.
3. **Write** the plan over with a concise standalone decision record: the task, final choices with their documented reasons (superseded proposals replaced by the final position), rejected alternatives only when they explain a choice, accepted limitations and deferred findings with reasons. No checklists, routing, review ceremony, raw test output, repeated findings, investigation notes or links to files being deleted. Don't invent rationale, treat proposals as approval or call unresolved findings fixed.
4. **Verify, lint, then delete.** Read the summary back: the sources' decisions and reasons are represented and formatting rules respected. Lint it (step 6). Only then delete the other identified, fully consolidated paths. Write/readback/verification/lint failure = no deletion. Partial deletion failure = keep the summary and what's left, report exactly what remains. Never delete the summary, directories, unrelated or shared artifacts, source/config, journals, session logs or Plannotator history. No archive, no rollback promise. Repeated Finalize preserves the existing summary's decisions without duplicates; no new inputs = no rewrite.
5. **Journals.** Update only journals/logs applicable instructions require, at their location and format: read first, no duplicates, the actual time written. Create one only when instructed. None required → skip, don't ask.
6. **Lint** every file Finalize changed: inspect the project's formatting/Markdown/doc lint config and scripts, run installed checks in non-fixing mode scoped to those files, fix only issues Finalize introduced, rerun after the last edit. No installs, config changes or unrelated reformatting. No applicable check → inspect manually and say so.
7. **Commit subject.** Exactly one single-line Conventional Commit subject for the whole task from its start (feat for features, fix for repairs; follow repo type/scope/length conventions). Breaking marker only for a real consumer-facing break in a positively identified public package. No body, trailer or version bump.

Don't edit source, instructions or unrelated docs, run tests or unrelated checks, install, or reopen Plannotator. Git writes only as in 3–5.

Report: summary path, deleted paths or exactly what remains, journals updated or "no journals required", lint results (or "manual"), evidence limitations, the subject.

## 2. Non-Git

Section 1 only, no Git status/diff/commit/push/PR/signing/auth. On success report and end (nothing to exit). Failures stay here for recovery. A repository that appeared later pauses the task and grants no Git authority.

## 3. Managed Git: authority and route

- Validate the task with `$H info` in the task root: exit 0 → managed task, continue; exit 3 → unmanaged checkout: section 1 only, no publication, say so; exit 1 → pause and report. Docs-only Finalize (no authority, or the user asked for docs only) ends after section 1 and stays in the worktree unless asked to exit.
- Authority comes from explicit human code/UI approval of this task or a direct publication instruction, never from task metadata, a standalone Review, an automated clean review or docs-only Finalize. Missing → docs only, say what's missing.
- Stop if section 1 is incomplete or failed. Make sure no owned UI server still runs.
- Unless the user already chose for this task, `AskUserQuestion` with exactly, in order: "Merge in-place (local only, no push)" (fast-forwards the original checkout's local base, keeps the task branch, discards all ignored task files and removes the merged worktree; pushing stays manual) / "Create or reuse a PR on GitHub" (pushes only the task branch). Cancelled → wait for chat, no default.

## 4. One signed task commit (both routes)

Run in the task root; quote resolved paths/refs, never interpolate task prose into shell.

1. **Inspect.** cwd, repository, branch `worktree-<id>` and HEAD match `$H info`; never commit in the source checkout or base branch. Read `git status --porcelain=v1 --untracked-files=all`, `git diff`, `git diff --cached`, `git log <start commit>..HEAD`. Identify the exact task paths; inspect new files; exclude secrets, ignored local config and unrelated changes (external artifacts aren't commit content). Mixed task/unrelated hunks or unrelated pre-staged content → ask; never unstage, stash or commit them silently. Stage with `git add -- <exact task paths>` only (never `.`, `-A`, `commit -a`), then read `git diff --cached` again.
2. **Commit.** `git commit -S -m <subject>` with the configured identity and normal hooks, Bash `timeout` ≤ 120000. Inspect non-secret `user.signingkey`, `gpg.format`, `gpg.program` if needed; a missing/ambiguous key or another signing mechanism → ask. Nothing staged → no empty commit; reuse user-made task commits that already hold the scope (no amend, no rewrite). After success or failure, check `git log --show-signature <start>..HEAD` and status: missing/invalid signatures, hook mutations, unrelated commits, conflicts or leftover task files pause publication. Never go unsigned or bypass hooks.
3. **GPG recovery.** Pinentry/passphrase prompts belong to the user's terminal, never chat or tool input. On a locked cache, missing pinentry or timeout, ask the user to unlock the configured key with a harmless signature in a terminal sharing Claude Code's GNUPGHOME/agent, for their shell; fish (POSIX shells the same), with the resolved non-secret key quoted: `printf '%s\n' 'Claude signing cache unlock' | gpg --local-user '<signing key>' --clearsign > /dev/null`. Then wait. No dummy commit, private-key inspection, preset passphrase, agent restart or config edit; cache lifetime is the user's gpg-agent policy. If it still can't work, offer a user-run signed commit in the task worktree.
4. **Resume** only after confirmation: re-inspect branch, HEAD, commit contents/signature and status (a timed-out commit may exist), retry only the unresolved step. Cancel/failure keeps files and index; explicit exit without publishing stays available.

## 5a. PR route

1. **Destination.** Resolve the existing SSH remote's push URL, GitHub host/owner/repo, head (task branch) and base explicitly. Several remotes/push URLs, forks, non-SSH or uncertain repo → ask; never rewrite remotes, fork or switch to HTTPS/tokens. gh auth is separate: unauthenticated or no access → the user runs gh auth in their terminal and confirms (never `gh auth login`/`setup-git`/`token` or credential output). Base = explicit user base, else `gh repo view <host/owner/repo> --json defaultBranchRef`; never the launch branch or a guess. Unresolved → pause.
2. **Push** only `git push <remote> refs/heads/<task branch>:refs/heads/<task branch>` with the existing `SSH_AUTH_SOCK`. No force, mirror, delete, base push, fetch/pull/rebase or rejection repair. Locked SSH key → ask the user to run `ssh-add -t 1h <key path>` (their lifetime/path) in a terminal with the same `SSH_AUTH_SOCK`, then wait; socket mismatch, unknown host, auth failure or divergence get their actual diagnosis. Can't unlock → offer a manual normal push. After every push (normal, uncertain or manual), compare `git ls-remote --heads <push URL> refs/heads/<task branch>` (the resolved push URL, not the fetch URL) with local HEAD before any PR query; missing or mismatched head pauses. Never claim push success from exit status alone.
3. **PR.** `gh pr list --repo <host/owner/repo> --head <task branch> --base <base> --state all --json number,url,state,isDraft,headRefName,headRefOid,baseRefName,headRepository`. Exact match = `headRepository` and `headRefName` are the resolved repo and task branch, `headRefOid` equals local HEAD, and `baseRefName` is the resolved base. Reuse an exact open ready match; draft/closed/merged, stale-head or ambiguous matches → ask. Else `gh pr create --repo <host/owner/repo> --head <task branch> --base <base> --title <title> --body <summary>` (task summary, actual checks, limitations; no private plans, logs or secrets; never `--dry-run`). After timeout, query before retrying; a pushed branch stays pushed. Verify URL/state/head/base.
4. **Report and return.** Commit/push/PR state, the verified URL, checks, limitations and the section 1 report. No CI polling, GitHub merge, local base update or branch/worktree deletion. Then `ExitWorktree` `keep` once and end the turn. Exit failure → keep the URL, report `pwd`, wait for chat.

## 5b. Local merge (no push, no gh)

1. **Task side, before exit.** Record task root, branch and HEAD from `$H info` and `git rev-parse HEAD`. `git status` shows no merge/rebase/cherry-pick/revert in progress, and the porcelain status is empty. Tracked/non-ignored pending files → pause; if the user explicitly keeps the worktree, merge but skip cleanup. Never delete files to get clean.
2. `ExitWorktree` `keep` (git can't target the source from inside the worktree). Confirm `pwd`; failure → report and stop.
3. **Source side, all with `git -C <sourceRoot>`.** Base = `git branch --show-current`. Its canonical toplevel and common git dir must equal the metadata `sourceRoot`/`repository`; base ≠ task branch. Detached, changed branch or start commit not an ancestor of HEAD → confirm the target in chat; never switch branches. Any in-progress operation → pause. Record evidence in a scratchpad file (never in commits or reports): HEAD, branch, `git diff --binary`, `git diff --cached --binary`, `git ls-files -s`, `git status --porcelain=v1 -z --untracked-files=all`, and hash, type and mode of each modified/untracked path. Never stage, commit, stash, reset or discard source work.
4. **Merge.** `git merge --ff-only -- <task branch>`. Unrelated pending source edits, staged content and untracked files don't block it; only Git's actual overwrite/conflict refusal does. Diverged history → explain and ask; only with permission `git merge --no-ff -S -m <subject> -- <task branch>` (hooks and GPG recovery as in 4), never with unrelated staged content (pause for a specifically authorized safe course). No rebase, squash, unsigned merge, reset, autostash, force or conflict resolution. Failure/timeout → inspect HEAD, status and merge state before any retry; conflicts stay for the user; no rollback claim, no cleanup.
5. **Verify.** `git merge-base --is-ancestor <task HEAD> HEAD`, base still checked out, no unresolved entries or in-progress operation, and the recorded evidence still matches for unrelated paths (contents, index entries, types, modes; an empty status isn't required). Check any merge commit's signature and hook effects. Mismatch or uncertainty pauses: don't claim untouched work without evidence. No push, fetch, pull, gh, CI or branch deletion.
6. **Cleanup**, from the source checkout: `$H cleanup <base> <task root>` (re-verifies, `git clean -fdX` in the task root only, leftover check, non-forced `git worktree remove`, branch kept). Report its output exactly. Failure (locked worktree, leftovers, nested repos) → report what remains; never `--force`, unlock or delete by hand. Skipped when keeping the worktree was chosen.
7. **Report** base and task branch, commit/merge state, cleanup result, the section 1 report, checks and limitations, and "nothing pushed; push remains manual." End the turn.
