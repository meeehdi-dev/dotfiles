# Finalize

Consolidate the current task's final decisions, perform instructed bookkeeping, and suggest one task-wide commit subject. Direct /finalize or an authorized handoff is sufficient instruction to start; do not ask for another approval, browser review, receipt/hash/provenance check, worktree comparison, or clean index. Git is optional evidence, not a prerequisite.

- Read the entire selected plan/reference and applicable instructions. If given a report, resolve its actual implementation plan through its references; ask if the target plan is ambiguous or missing. Keep the existing implementation-plan path as the surviving summary (normally ~/.pi/plans/<project-key>/<task>.md); shared per-artifact path overrides still apply. Consult source/history only as needed to understand the whole implemented task; do not claim checks were rerun here.
- Establish a concrete set of eligible source paths before editing: only the current task's implementation plan, related plans, clarifications, reviews, and UI feedback. Read these inputs completely, following task-related references and paths in handoff notes, not every historical link. Inspect relevant project artifact directories when needed for clearly related reports that reference the plan but are not linked from it. Do not bulk-read project history or infer membership from filename prefix or modification time alone. A linked file outside normal artifact folders is not automatically eligible for deletion.
- Ask before discarding contents when task membership, shared artifacts, target paths, conflicting decisions, unreadable inputs, or relevant outcomes/reasons remain unclear. Preserve work and continue in this session after clarification; do not invent rationale, treat proposals as approval, or call unresolved findings fixed.
- Replace the implementation plan with a concise standalone final decision record identifying the task and its final choices with documented reasons. Merge repeated choices, replace superseded proposals with the final position, and keep rejected alternatives only when they explain that position. Retain accepted limitations and deferred findings with their reasons. Exclude implementation checklists, session routing, review ceremony, raw test output, repeated findings, temporary investigation notes, and redundant source inventories. Do not leave links to artifacts being deleted.
- Fully read and consolidate all eligible inputs before replacing the plan. Write the complete summary at the target plan path, then read it back and verify that the sources' final decisions and reasons are accurately represented and applicable formatting rules are respected. Only after successful verification delete the exact other task artifact paths already identified and fully consolidated. This is the Finalize-only exception to preserving input reports and earlier reviews; it intentionally removes detailed history without an archive. Never delete the surviving summary, parent directories, unrelated/shared artifacts, source/configuration files, journals, session logs, or Plannotator history.
- If summary write/readback or verification fails, perform no cleanup. If deletion partially fails, preserve the summary and remaining files and report exactly what remains; clarify when needed and continue here. Do not promise transactional rollback or automatic recovery. On repeated Finalize, read the existing summary, preserve its decisions, avoid duplicate entries and unrelated cleanup; no new task inputs means no substantive rewrite.
- Update only journals/logs explicitly required by applicable instructions, at their named locations and in the existing format. Read targets first, preserve entries, avoid duplicates on resumption, and use the time actually written. Create a required log only when its creation/location is instructed. Existing logs alone are not authorization. If no journals are required, skip journal writes and ask no journal-location question. Ask about genuinely ambiguous/unreadable required bookkeeping. Consolidation and journal updates need no automatic new review.
- After any documentation/bookkeeping edits, verify all files changed in Finalize against applicable project formatting, Markdown, and documentation lint rules. Inspect existing configuration/scripts first; run relevant installed checks in non-fixing mode, scoped to those files where supported. Correct only formatting/lint issues introduced by Finalize within its allowed edit scope, then rerun the affected checks after the last edit. Do not install tools, change configuration, or reformat unrelated content. If no automated check applies, inspect the changed text against the applicable rules and state that verification was manual. Report actual results, unavailable checks, and unresolved or pre-existing issues; do not claim earlier checks cover later edits. If summary formatting verification fails, perform no artifact cleanup.
- Suggest exactly one single-line Conventional Commit subject for the complete task from its start, not only final fixes, UI follow-up, or journals. Features normally use feat and repairs fix; follow repository type/scope/length conventions without inventing a universal length limit. No body, footer, trailer, wrapper, or Git command in the subject.
- Use a breaking marker only for an actual consumer-facing break in a positively identified public library/package. A manifest alone is insufficient; standalone and unknown projects do not use it. Do not bump versions or edit releases.
- Do not edit source, instructions, or unrelated docs; edit plans/reports only for the consolidation above. Do not run tests, unrelated checks, or installs, or reopen Plannotator as an automatic final phase; only the scoped documentation formatting/lint checks above are automatic. All Git writes remain the user's: no stage/unstage, commit/push/amend, reset/stash/clean, hooks, or Git configuration changes. Never invent a commit/hash.
- Finish with the summary path, cleanup results or exact remaining artifacts/limitations, journal paths updated or "no journals required," formatting/lint verification results and any evidence limitations, and the one suggested subject. No completion tool or next session is needed; the conversation remains usable.
